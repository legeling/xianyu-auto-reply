## 商品记录约定

每项商品使用稳定的英文目录名，目录内 `product.json.id` 与目录名一致。ID 在标题、售价变更后保持不变，用于关联同步记录。

| 字段 | 含义与维护方式 |
| --- | --- |
| `id` | 本地稳定标识，字符串 |
| `kind` | `data` 数据、`script` 脚本、`service` 开发服务、`account` 已有账号类商品 |
| `status` | `planned` 尚未细化的方案；`draft` 正在准备发布资料；`listed` 已取得并核验线上商品ID的记录 |
| `currency` | 本目录报价使用 `CNY`，`listing.price` 单位为元 |
| `listing` | 标题、描述、售价、图片、数量、分类及所在地；字段名称沿用后台发布合同 |
| `listing.images` | 相对于商品目录的仓库图片路径。上传后取得的后台路径写入本次发布载荷，不覆盖本地图片路径 |
| `delivery.mode` | 计划交付方式：`automatic` 自动发货、`manual` 人工交付，未确定为 `null`；该字段不表示线上开关已启用 |
| `delivery.type` | 确定自动发货后采用后台卡券类型 `text/data/image/api`；未确定为 `null` |
| `delivery.content_file` | 实际发货载荷的本机文件路径；未配置为 `null`。文件必须包含真实交付内容，采用后台 `CardCreate` 合同 |
| `xianyu` | 目标账号及素材、商品、卡券ID；发布、绑定和回读成功后写回结果 |
| `xianyu.last_checked_at` | 最后核验时间，带时区的 ISO 8601 字符串；未核验为 `null` |
| `notes` | 来源说明、尚未核实的事实、未完成事项 |

`null` 表示尚未确定，空的图片或卡券列表表示尚未登记，不使用示例下载网址、虚构卡密或猜测价格补齐。`product.json` 是商品档案，**不能整个作为 `publish single --data-file` 的请求**；发布合同见 `backend-web/app/api/routes/product_publish.py`，发货合同见 `backend-web/app/api/routes/cards.py`。

仓库保存可公开的标题、文案、价格、商品范围和宣传图。原始数据、大型交付包、下载提取码、卡密、密码、API Key、Cookie、token 留在受控的仓库外文件中，`content_file` 只引用路径。需要暂存本机发货载荷时使用已忽略的 `.cache/product-sync/<id>/`，文件权限设为 `0600`；该目录不作为商品档案或唯一交付备份。

## 从本地到线上

目前复用现有 `publish/cards/delivery/items` 命令执行同步，还没有“一键扫描整个商品目录并自动同步”的 CLI 命令。每次按一个商品执行，文件解析和准备阶段不调用收费服务、不发布商品、不发货。

1. **补齐本地资料。** 核对标题、描述、实际售卖范围与交付包；填写价格、数量、所在地和图片。数据商品的日期、字段、文件清单与真实交付物一致；服务商品写清功能、周期、验收及售后范围。
2. **准备发布载荷。** `publish check-account` 检查目标账号；`publish upload-images` 上传仓库图片；`publish recommend-category` 获取平台分类与属性并写回商品档案。将 `listing` 转成后台规范请求，并加入 `xianyu.account_id`，保存本次载荷供核对。已有 `item_id` 的商品先回读核对，不能当新商品再次发布。
3. **发布并记录结果。** 新商品用 `publish single`，或先创建素材再用 `publish batch`。将返回的素材ID、任务ID和商品ID记录下来；批量提交后只查 `publish status` 与 `publish logs`，不反复提交。用 `items sync` 从闲鱼拉回商品，再用 `items list` 核验并写回 `status/item_id/last_checked_at`。
4. **配置交付。** 对可实际自动交付的商品，用真实发货文件创建停用的卡券，绑定该商品，读取核对后启用卡券；将 `card_ids` 写回档案。定制服务按约定完成后人工交付。账号级发货开关影响同账号其他商品，修改前先读取 `delivery config` 并核对现有商品关联。
5. **核验并记账。** `delivery inspect` 核对账号、商品、卡券和规则；保存本次请求、结果及时间，将已核验的关联写回档案。实际订单成功发货必须由订单状态和 `delivery logs` 证明，不能仅凭开关已打开宣称完成。

命令和参数示例见 [CLI 上架与自动发货管理](../cli-operations.md)。每次商品同步的请求与结果可暂存 `.cache/product-sync/<id>/<本次运行目录>/`，其中只有脱敏结果及确认过的业务ID写回商品档案；失败时保留已完成步骤，不自动重发发布请求。

普通卖家的现有商品编辑能力有限：`items update-local` 只改后台本地记录，不修改闲鱼页面；平台改价/库存及编辑命令当前适配鱼小铺。修改已有商品时先确定实际可用路径，不能通过重复上架冒充同步成功。

## 撤销与部分失败

发布成功而发货配置失败时保留线上商品ID，继续修复交付配置，不重复创建商品。结果不明时先查发布日志、任务状态和闲鱼商品记录，再决定下一步。

需要撤销本次新商品时按已记录ID执行 `items offline`；停用本次卡券用 `cards disable`，解除指定关联用 `cards unbind`。保留历史商品ID和操作记录，不清空同账号其他商品的卡券，不删除既有业务记录。涉及账号级开关时恢复同步前记录的原值。
